# Плейбук оркестрации — качество при минимуме токенов

Модели и правила делегирования — в `~/.gemini/config/rules/AGENTS.md`. Здесь — **как работать на практике**.

## 1. Выбор модели в меню чата — дерево решений
```text
Правка текста / цвета / отступа / 1 мелкий баг?      → Gemini 4 Hydrogen (Medium), без субагентов
Обычная фича, 1–3 файла / зоны?                      → Gemini 4 Neon (Medium)  ← режим по умолчанию
Эпик: 4+ модулей, нужен swarm?                       → Orchestrator (Gemini 4 Neon High)
Новая подсистема / схема БД / крупный рефакторинг?   → Gemini 4 Carbon (Medium): только план → файл → закрыть чат
Квота Gemini просела или тяжёлый TS-рефакторинг?     → Claude Sonnet 5.5 (Medium)
Баг не решён за 2 попытки / ревью перед релизом?     → Claude Opus 5.5 (Medium): короткая сессия
```
Не используем: `Gemini 4 Argon`, `Gemini 3.8 Flash` (выводятся).

## 2. Цикл «План → Исполнение → Проверка → Деплой»
1. **План** (только для крупного): Carbon или Opus пишет `specs/NN-<фича>.md` — зоны, файлы, контракты типов, критерии готовности. Чат закрыть.
2. **Исполнение**: новый чат на Neon Medium / Orchestrator читает спеку и раздаёт задачи по зонам из `AGENTS.md §4`.
3. **Проверка**: `build-verifier` один раз после пачки правок. FAIL → точечная задача исполнителю, не правка в основном контексте.
4. **Ревью** (по желанию, для критичного): один ход Opus или Sonnet по `git diff`, не по всему проекту.
5. **Деплой**: `npx -y vercel --prod --yes` — делает сам оркестратор.

## 3. Шаблоны промптов

**Обычная фича (Neon Medium):**
```text
Задача: <что сделать>. Зоны: <UI / данные / каталоги>.
Делегируй: ui-designer и backend-worker с Model "flash", в брифе — точные пути и "ответ ≤10 строк".
Сам код не пиши, кроме стыковки. В конце — build-verifier (flash_lite), затем деплой.
```

**Эпик (Orchestrator Neon High):**
```text
Прочитай specs/NN-<фича>.md. Подними swarm: UI → gemini-4-hydrogen-low, данные → gemini-4-hydrogen-medium,
сложный движок → gemini-4-neon-medium, verifier → gemini-4-hydrogen-low. Файлы между воркерами не пересекаются,
src/types/game.ts меняет первым backend-воркер. Отчёты воркеров ≤10 строк.
```

**План (Carbon Medium / Opus):**
```text
Спроектируй <фичу>. Не пиши код. Результат — specs/NN-<фича>.md: зоны, файлы, изменения типов, API, критерии готовности, порядок работ.
```

**Тяжёлый баг (Opus / Sonnet):**
```text
Баг: <симптом, шаги, ожидаемо/фактически>. Уже пробовали: <что>. Подозрительные файлы: <пути>.
Найди корневую причину, предложи минимальный фикс и внеси его. Без рефакторинга вокруг.
```

## 4. Гигиена токенов
- Одна фича — один чат; разросся → `/compact` или новый чат.
- Давай пути к файлам — агент не будет сканировать проект.
- Не проси «проверь всё» — проси проверить конкретный diff или экран.
- `/plan` и `/boost` — только для действительно сложного; `swarm` — только для 4+ независимых модулей.
- Кончилась квота воркера → `swarm{action:"model", name, model:"gpt-oss-120b-medium"}`, не `kill`.
